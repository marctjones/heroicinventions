# Coordinator handoff, 2026-10-07

For a fresh session taking over coordination. The previous coordinator's context had grown large; this is everything needed to carry on.

## How the work is organised

- **Develop on `main`**, commit often, push. Tag releases as checkpoints (`v0.1.0-alpha` exists).
- **The coordinator merges; workers branch.** Subagents run in git worktrees (`isolation: worktree`) and commit on their branch `worktree-agent-<id>`; they never push or merge. The coordinator reviews (`git diff --stat main...<branch>`), merges with `--no-ff`, rebuilds, runs the suites, looks at a frame, then pushes.
- **Peer session "Game component and machine skins"** (`local_a8d2882b-cdf9-4d89-9f70-6d3221650eb5`) owns the look (art-direction.md). It messages when a branch is ready (`art/...` in `.claude/worktrees/skins`). It stays out of camera/profile code, MachineView.Gears.cs, Boiler.cs and MachineRuntime.cs; the coordinator stays out of BuildEnvironment, ShowSky, SkyLook.cs, Skins.cs and materials.
- **Use subagents with fresh context for each piece of work** and keep the coordinator's own context small: don't read subagent transcripts, read their reports.

## Rules the owner has set (also in Claude's memory for this repo)

- A machine works only when a trace shows it doing its job against a number worked out beforehand; exit 0 is not a check. Before tagging a release, inspect machines not yet checked in detail (the audit below).
- Visual style: clear visibility over realism in colouring and light levels (the physics stays realistic). Measure with `python3 tools/legibility.py <shots>` (targets: sd ≥ 40, |separation| ≥ 50).
- GUI checks never take the owner's focus: `tools/gui-check.sh` (background window, scripted input, `shot PATH`), never computer-use. The shell is zsh: use arrays (`L=(a b c); for m in $L`), not space-separated strings.
- Allow, don't forbid: poor designs and materials stay buildable and fail for a physical, visible reason.
- Don't make big engine changes to get one machine working; build components that can really be modelled, each with an issue.
- New features get an issue first.
